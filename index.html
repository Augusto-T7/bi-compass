ETL — Extraer, Transformar, Cargar
ETL — Extract, Transform, Load
Extract · Transform · Load
Es el proceso central de Power Query. Extraes datos de una fuente (Excel, SQL, CSV), los transformas (limpias, filtras, renombras, combinas) y los cargas al modelo de datos.

Analogía: Un chef recibe ingredientes crudos del mercado (Extract), los lava, corta y mezcla según la receta (Transform), y los sirve en el plato al cliente (Load). Sin transformación, los ingredientes crudos no son una comida.
This is the core process of Power Query. You Extract data from a source (Excel, SQL, CSV), Transform it (clean, filter, rename, combine), and Load it into the data model.

Analogy: A chef receives raw ingredients from the market (Extract), washes, cuts and mixes them following a recipe (Transform), and serves the finished dish to the customer (Load). Without transformation, raw ingredients are not a meal.

Calidad de Datos
Data Quality
Null · Duplicate · Type Error
Un dataset tiene 3 problemas principales: Nulos (campos vacíos), Duplicados (registros repetidos) y Errores de tipo (un número guardado como texto).

Power BI te muestra la calidad de cada columna con barras de color en el Column Quality view. Verde = válido, Amarillo = vacío, Rojo = error.
A dataset has 3 main problems: Nulls (empty fields), Duplicates (repeated records) and Type errors (a number stored as text).

Power BI shows column quality with color bars in Column Quality view. Green = valid, Yellow = empty, Red = error.

Combinar Datos
Combining Data
Merge · Append · Join
Merge: Une dos tablas por una columna común (como un VLOOKUP, pero mejor). Append: Apila dos tablas con las mismas columnas (agregar nuevas filas).

Merge: Joins two tables by a common column (like VLOOKUP, but better). Append: Stacks two tables with the same columns (add new rows).

Merge types: Left Outer, Right Outer, Inner, Full Outer. The PL-300 exam asks about this frequently.

Query Folding
Query Folding
Performance · SQL Push-down
Cuando Power Query puede traducir tus transformaciones en SQL y ejecutarlas en el servidor de datos (no en tu PC), eso se llama Query Folding. Es más rápido y eficiente.

Si agregas un paso personalizado en M que no puede traducirse, el folding se rompe — todo lo que sigue corre localmente.
When Power Query can translate your transformations into SQL and run them on the data server (not your PC), that's called Query Folding. It's faster and more efficient.

If you add a custom M step that can't be translated, folding breaks — everything after runs locally.

Tipos de Datos
Data Types
Text · Number · Date · Boolean
El tipo de dato de una columna determina qué operaciones puedes hacer. Error crítico: una fecha guardada como texto no puede usarse en cálculos de tiempo. Un ID numérico guardado como número puede sumarse accidentalmente.

Regla: IDs → Texto. Importes → Decimal. Fechas → Date.
The data type of a column determines what operations you can perform. Critical error: a date stored as text can't be used in time calculations. A numeric ID stored as number can be accidentally summed.

Rule: IDs → Text. Amounts → Decimal. Dates → Date.

Pivot, Unpivot y Transpose
Pivot, Unpivot and Transpose
Reshape · Wide to Long · Long to Wide
Pivot: convierte filas únicas en columnas (Long → Wide). Ejemplo: meses como filas → meses como columnas.

Unpivot: lo opuesto — columnas a filas (Wide → Long). Esencial para normalizar datos de Excel mal estructurados.

Transpose: intercambia filas por columnas completamente.

Regla PL-300: Si recibes un Excel con columnas "Enero, Febrero, Marzo..." como headers, necesitas Unpivot para crear una columna "Mes" y una columna "Valor" — formato correcto para DAX.
Pivot: converts unique rows into columns (Long → Wide). Example: months as rows → months as columns.

Unpivot: the opposite — columns to rows (Wide → Long). Essential for normalizing poorly structured Excel data.

Transpose: swaps rows and columns completely.

PL-300 rule: If you receive an Excel with "January, February, March..." as column headers, you need Unpivot to create a "Month" column and a "Value" column — correct format for DAX.

Group By — Agrupar y Agregar
Group By — Group and Aggregate
SUM · COUNT · AVG · MIN · MAX
Group By en Power Query agrupa filas por una o más columnas y aplica una función de agregación.

Ejemplo: tabla de 50,000 transacciones → Group By Product, SUM(Sales) → tabla de 200 productos con total de ventas.

Diferencia clave con DAX: Group By ocurre en la capa de transformación (antes del modelo). Las medidas DAX agregan en el momento de la consulta. Usar Group By reduce el tamaño del modelo — mejora performance.

Pregunta examen: "¿Cuándo usarías Group By en Power Query en lugar de una medida DAX?" → Cuando necesitas reducir granularidad permanentemente antes de cargar.
Group By in Power Query groups rows by one or more columns and applies an aggregation function.

Example: table of 50,000 transactions → Group By Product, SUM(Sales) → table of 200 products with total sales.

Key difference from DAX: Group By happens in the transform layer (before the model). DAX measures aggregate at query time. Using Group By reduces model size — improves performance.

Exam question: "When would you use Group By in Power Query instead of a DAX measure?" → When you need to permanently reduce granularity before loading.

Reference vs Duplicate Query
Reference vs Duplicate Query
Linked · Independent · Performance
Duplicate: crea una copia independiente de la query. Cambios en el original no afectan la copia. Doble procesamiento = más lento.

Reference: crea una query que depende del resultado de otra. Si la original cambia, la referenciada también cambia. Un solo procesamiento = más eficiente.

Caso de uso real: Tienes una query base "Sales_Raw". Creas References para "Sales_Retail" y "Sales_Wholesale" con diferentes filtros. La limpieza ocurre una sola vez en Sales_Raw — no tres veces.

Regla PL-300: Usa Reference cuando las queries comparten transformaciones base. Usa Duplicate solo cuando necesitas una rama completamente independiente.
Duplicate: creates an independent copy of the query. Changes to the original don't affect the copy. Double processing = slower.

Reference: creates a query that depends on another query's result. If the original changes, the referenced one changes too. Single processing = more efficient.

Real use case: You have a base query "Sales_Raw". Create References for "Sales_Retail" and "Sales_Wholesale" with different filters. Cleaning happens once in Sales_Raw — not three times.

PL-300 rule: Use Reference when queries share base transformations. Use Duplicate only when you need a completely independent branch.

PL-300 exam: Questions about parameters focus on making models dynamic and portable between environments (dev/prod).

Credenciales y Niveles de Privacidad
Credentials and Privacy Levels
None · Public · Organizational · Private
Credenciales: definen cómo Power BI se autentica con una fuente de datos (usuario/contraseña, OAuth, clave API, Windows auth).

Niveles de privacidad controlan si los datos de una fuente pueden combinarse con datos de otra:
• None: sin restricciones (solo desarrollo local)
• Public: datos públicos, pueden combinarse libremente
• Organizational: solo se combinan con fuentes del mismo nivel o inferior
• Private: aislado — nunca se combina con otras fuentes

Error común: Si ves "Formula.Firewall" error al combinar fuentes, el problema son los niveles de privacidad incompatibles.
Credentials: define how Power BI authenticates with a data source (username/password, OAuth, API key, Windows auth).

Privacy levels control whether data from one source can be combined with data from another:
• None: no restrictions (local development only)
• Public: public data, can be combined freely
• Organizational: only combines with same or lower level sources
• Private: isolated — never combines with other sources

Common error: If you see a "Formula.Firewall" error when combining sources, the issue is incompatible privacy levels.

Configurar Carga de Datos
Configure Data Loading
Enable Load · Report Connection Only · Staging
No todas las queries deben cargarse al modelo de datos. Power Query permite tres comportamientos:

• Enable Load: la query se carga al modelo (tabla visible en Power BI)
• Disable Load: la query existe pero no genera tabla — se usa como staging o paso intermedio
• Include in Report Refresh: controla si la query se actualiza en cada refresh

Patrón recomendado: Queries de staging (limpieza base) con Disable Load. Solo las tablas finales con Enable Load. Resultado: modelo más limpio y rápido.

Error común PL-300: Cargar todas las queries intermedias al modelo — genera tablas innecesarias que confunden al usuario final.
Not all queries need to be loaded into the data model. Power Query allows three behaviors:

• Enable Load: the query loads into the model (visible table in Power BI)
• Disable Load: the query exists but generates no table — used as staging or intermediate step
• Include in Report Refresh: controls whether the query updates on each refresh

Recommended pattern: Staging queries (base cleaning) with Disable Load. Only final tables with Enable Load. Result: cleaner, faster model.

Common PL-300 error: Loading all intermediate queries into the model — creates unnecessary tables that confuse the end user.

Resolver Errores de Importación
Resolve Data Import Errors
Error · null · Remove Errors · Replace
Los errores de importación ocurren cuando Power Query no puede procesar un valor. Aparecen como Error en la celda.

Causas más comunes:
• Conversión de tipo fallida (texto "N/A" en columna numérica)
• Caracteres especiales en fuentes CSV
• Fórmulas rotas en Excel origen
• Columnas renombradas en la fuente que rompen Applied Steps

Soluciones en Power Query:
• Remove Errors: elimina filas con error
• Replace Errors: reemplaza el error con un valor (ej: 0 o null)
• Keep Errors: conserva solo las filas con error (para auditarlas)

Regla de negocio: Nunca elimines errores sin entender por qué ocurren. Un error sistemático indica un problema en la fuente.
Import errors occur when Power Query cannot process a value. They appear as Error in the cell.

Most common causes:
• Failed type conversion (text "N/A" in numeric column)
• Special characters in CSV sources
• Broken formulas in source Excel
• Renamed columns in source that break Applied Steps

Power Query solutions:
• Remove Errors: delete rows with errors
• Replace Errors: replace the error with a value (e.g. 0 or null)
• Keep Errors: keep only error rows (to audit them)

Business rule: Never remove errors without understanding why they occur. A systematic error indicates a source problem.

Crear y Transformar Columnas
Create and Transform Columns
Custom Column · Conditional · Split · Extract
Power Query permite crear columnas nuevas o transformar las existentes sin escribir código complejo:

• Custom Column: columna calculada con fórmula M. Ejemplo: [Price] * [Quantity]
• Conditional Column: lógica if/then/else visual. Ejemplo: si Region = "North" entonces "Zone A" sino "Zone B"
• Split Column: divide texto por delimitador. Ejemplo: "New York, USA" → columna City + columna Country
• Extract: extrae parte de texto (primeros N caracteres, texto antes de delimitador)

Diferencia con DAX: Columnas creadas en Power Query son físicas y estáticas. Columnas calculadas en DAX se recalculan en memoria. → Módulo 3 cubre columnas calculadas DAX.
Power Query lets you create new columns or transform existing ones without complex code:

• Custom Column: calculated column with M formula. Example: [Price] * [Quantity]
• Conditional Column: visual if/then/else logic. Example: if Region = "North" then "Zone A" else "Zone B"
• Split Column: splits text by delimiter. Example: "New York, USA" → City column + Country column
• Extract: extracts part of text (first N chars, text before delimiter)

Difference from DAX: Columns created in Power Query are physical and static. DAX calculated columns recalculate in memory. → Module 3 covers DAX calculated columns.

Regla: Pie charts solo cuando tienes 2-3 categorías y quieres mostrar parte del todo. Para rankings y comparaciones, usa barras.
Rule: Pie charts only when you have 2-3 categories and want to show part of a whole. For rankings and comparisons, use bars.

✅ Solución — Paso 3 está en posición incorrecta Solution — Step 3 is in the wrong position
